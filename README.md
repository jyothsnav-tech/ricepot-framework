# ricepot-framework
Structured prompt engineering methodology designed specifically for quality assurance (QA), software testing, and enterprise AI automation tasks

## About RICEPOT

RICEPOT is a framework for structuring prompts by defining seven key components:

* **R — Role**
* **I — Instructions**
* **C — Context**
* **E — Example**
* **P — Parameters**
* **O — Output**
* **T — Tone**

## RICEPOT Breakdown

| Letter | Component        | Description                                                                                                              |
| ------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **R**  | **Role**         | Defines the persona the AI should adopt. Example: Expert QA Automation Engineer.                                         |
| **I**  | **Instructions** | Provides specific, step-by-step commands and constraints, including mandatory rules and "don't" lists.                   |
| **C**  | **Context**      | Provides background information to help the AI understand the why and where. Example: Salesforce Login Page description. |
| **E**  | **Example**      | Provides an example, code snippet, or format to guide the expected style. Example: PageFactory implementation.           |
| **P**  | **Parameters**   | Defines constraints related to quality, accuracy, and style. Example: Production-level code with zero bad practices.     |
| **O**  | **Output**       | Defines exactly what artifacts or information the AI should produce. Example: Only code, with no comments.               |
| **T**  | **Tone**         | Defines the desired communication style. Example: Technical, precise, and code-focused.                                  |

## RICEPOT for QA

Potential applications of RICEPOT include:

* Test case generation
* Test scenario identification
* Requirements analysis
* Test data generation
* API testing
* Automation code generation
* Test coverage analysis
* Defect analysis
* QA documentation
